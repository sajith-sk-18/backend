# Deploy to Hostinger — https://flurotech.in (single origin)

Everything on **one domain**, so the browser never makes a cross-origin request and
CORS cannot break the site:

| Part | URL |
|---|---|
| Storefront | `https://flurotech.in/` |
| Admin panel | `https://flurotech.in/admin/` |
| API | `https://flurotech.in/api/` |

This supersedes `DEPLOY-HOSTINGER.md` (three subdomains) and `DEPLOY-rfgd.md`
(InfinityFree). Same single-origin layout as rf.gd, on a real host.

## Target layout on the server

```
~/domains/flurotech.in/
├── laravel-api/                 ← the Laravel app, OUTSIDE the document root
│   ├── app/ bootstrap/ routes/ vendor/ storage/ …
│   ├── public/                  ← unused in production (see note)
│   └── .env                     ← from deploy/hostinger/env.production.example
└── public_html/                 ← the document root for flurotech.in
    ├── index.html, assets/, products/…   ← customer-site/dist/*
    ├── .htaccess                         ← ships in customer-site/dist/
    ├── sitemap.xml, robots.txt           ← generated by the build
    ├── admin/                            ← admin-panel/dist/*
    │   ├── index.html, assets/
    │   └── .htaccess                     ← ships in admin-panel/dist/
    └── api/
        ├── index.php            ← deploy/hostinger/api-index.php
        ├── .htaccess            ← deploy/hostinger/api-htaccess
        └── storage → ../../laravel-api/storage/app/public   (symlink)
```

🔴 **The app stays outside `public_html`.** Only `index.php` and `.htaccess` go in
`public_html/api/`. Putting the project itself under the document root is what
exposes `.env`, `vendor/` and any stray script at a public URL.

## Order matters — API first

The storefront's build **fetches products from the API** and writes prerendered
`products/<id>/index.html` for SEO. Build the frontends only once
`https://flurotech.in/api/products` returns JSON, or the product pages ship with no
SEO content (the build warns and continues).

---

## 1) Domain + database (hPanel)

1. **Websites → Add website** for `flurotech.in` (or point the existing one) so
   `~/domains/flurotech.in/public_html` exists.
2. **Databases → MySQL**: create a database + user, note name / user / password.
3. **PHP version**: set **8.2 or 8.3** (Laravel 11 requires ≥ 8.2).
4. **SSL**: issue the free certificate and turn **Force HTTPS** on.

## 2) API

Upload `backend/` to `~/domains/flurotech.in/laravel-api/` (git clone over SSH, or
upload a zip and extract in File Manager). Then:

```bash
cd ~/domains/flurotech.in/laravel-api
cp deploy/hostinger/env.production.example .env    # then edit the DB_* values
composer install --no-dev --optimize-autoloader
php artisan key:generate
php artisan migrate --force --seed
php artisan config:cache && php artisan route:cache

# front controller + rewrite rules into the document root
mkdir -p ~/domains/flurotech.in/public_html/api
cp deploy/hostinger/api-index.php  ~/domains/flurotech.in/public_html/api/index.php
cp deploy/hostinger/api-htaccess   ~/domains/flurotech.in/public_html/api/.htaccess

# uploaded product images (APP_URL=https://flurotech.in/api makes asset() URLs
# resolve to /api/storage/..., which is exactly this link)
ln -s ~/domains/flurotech.in/laravel-api/storage/app/public \
      ~/domains/flurotech.in/public_html/api/storage

chmod -R 775 storage bootstrap/cache
```

**No SSH on the plan?** Run `composer install` locally and upload `vendor/` with the
rest; use hPanel's **Databases → phpMyAdmin** to import a dump taken from a local
`migrate --seed`; and because File Manager cannot create a symlink, copy
`storage/app/public` into `public_html/api/storage` after each image upload (or ask
Hostinger support to enable SSH — it is available on Premium and above).

**Smoke test:** `https://flurotech.in/api/products` → JSON.

## 3) Frontends

Both production env files are already committed and point at `https://flurotech.in`:
`customer-site/.env.production`, `admin-panel/.env.production`.

```bash
cd customer-site && npm ci && npm run build        # → dist/ (+ prerender, sitemap, robots)
cd ../admin-panel && npm ci && ADMIN_BASE_PATH=/admin/ npm run build   # → dist/
```

🔴 **`ADMIN_BASE_PATH=/admin/` is mandatory.** A plain `npm run build` bakes `base: '/'`
(the Cloudflare Pages default, see `admin-panel/vite.config.js`), the panel then asks for
`/assets/*.js`, the storefront's SPA fallback answers with its own `index.html`, strict
MIME checking rejects it and **the admin loads blank**.

Upload:
- everything inside `customer-site/dist/` → `public_html/`
- everything inside `admin-panel/dist/` → `public_html/admin/`

Both `dist/` folders contain a **hidden `.htaccess`** — enable "show hidden files" in
your FTP client or it will not be uploaded, and every deep link will 404.

## 4) Verify

| Check | Expected |
|---|---|
| `https://flurotech.in/` | storefront, products visible, no console errors |
| `https://flurotech.in/products` | 8+ products from the API |
| `https://flurotech.in/products/1/` (view source) | real `<title>` + `"@type":"Product"` |
| `https://flurotech.in/admin/` | admin login (not the storefront) |
| `https://flurotech.in/admin/products` **direct load / refresh** | stays in the admin |
| `https://flurotech.in/api/products` | JSON |
| `https://flurotech.in/.env` | **404** — if it returns content, stop and fix the layout |
| response header on `/admin/` | `x-robots-tag: noindex, nofollow, noarchive` |

Then change the seeded admin password (`admin@example.com` / `password`) — log in and
change it, or run `php artisan tinker` / `deploy/set-admin-password.php` on the server.

## Notes

- `public/_redirects` and `public/_headers` are **Cloudflare Pages** files. Apache
  ignores them, so they are harmless on Hostinger — but `_redirects` still 302s
  `/admin` to `fluro-admin.pages.dev` on the *Cloudflare* deployment. Retire the
  Pages/Railway deployments once flurotech.in is verified, or they keep serving a
  second, stale copy of the site (and compete with it in search).
- Re-run `npm run build` and re-upload whenever products change, so the prerendered
  pages and `sitemap.xml` stay current.
- Google Search Console: `public/google33fd6ed204d674f4.html` ships with every build,
  so the HTML-file verification works on the new domain too; submit
  `https://flurotech.in/sitemap.xml`.
